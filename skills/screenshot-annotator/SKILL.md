# screenshot-annotator

제품 매뉴얼용 스크린샷에 **영역선 + 리더선 + 번호 배지**를 그린다.

Figma에 그릴 때는 대상 파일 키와 페이지 id를 **작업 시작 시 사용자에게 확인**한다.
Figma 없이 쓸 때는 `render.py`로 PNG를 내보낸다 — 좌표·스타일은 양쪽이 같다.

---

## 0. 불변식 — 이걸 어기면 반드시 어긋난다

지금까지 발생한 좌표 오류는 **전부** 아래 4가지 중 하나였다. 작업 전에 확인한다.

### 0-1. 측정은 **노드 export** 위에서만 한다

원본 이미지(`rawImages`)나 직접 리사이즈한 로컬 사본으로 좌표를 재면 안 된다.
이미지 fill은 `scaleMode: FILL`이라 **비율이 다르면 잘라낸다(crop)**.

| 원본 | 박스 | 결과 |
|---|---|---|
| 1918×965 (1.988) | 1040×524 (1.985) | crop 무시 가능 |
| **1920×1009 (1.903)** | 1040×524 (1.985) | **상·하 11px씩 잘림** → 위치별로 다르게 밀림 |

```
y_render ≈ y_squash × 1.043 − 6      # 1920×1009 케이스의 실제 어긋남
```

→ 반드시 `download_assets(nodeId=<그 rect>, defaultScale=1)`로 **렌더된 픽셀**을 받아
   그 위에서 측정·라우팅·halo 판정을 **전부** 수행한다.

### 0-2. 좌표 기준계는 상수 하나로 고정

```
IMG_X, IMG_Y = 230, 60          # 프레임 안 이미지 원점
frame_x = IMG_X + image_x
frame_y = IMG_Y + image_y       # 밴드가 여러 개면 + BAND_Y
```

밴드마다 이미지 y 오프셋을 다르게 두면 확대 도해의 표시 박스가 어긋난다(L4 사례, 68px).

### 0-3. Figma `node.x/y`는 **부모 상대 좌표**

섹션 안 프레임에 절대 좌표를 넣으면 프레임이 캔버스 저편으로 날아가 "안 보인다".
`absoluteBoundingBox`로 검증한다.

따라서 **섹션을 옮길 때 자식을 같이 옮기면 두 번 밀린다.** `sec.y = ny` 한 줄이면 끝이다.
(`clone()` 후 델타를 자식에도 더했다가 51프레임이 전부 섹션 밖으로 나갔다.)

### 0-4. 번호의 뜻은 **절차문**에서 읽는다 (2.2 화면 구성 표가 아니다)

같은 화면이라도 `2.2 화면 구성` 표의 번호와 `2.3 조작 절차`의 번호는 **다른 요소**를
가리킨다. 절차판을 그리면서 화면 구성 표의 라벨을 쓰면 번호는 맞고 대상이 틀린다.

실제 사례 — A-04-2 (1) 노드 상태:

| 번호 | 화면 구성 표(shot18) | **절차문 A-04-2** | v9에 그려져 있던 것 |
|---|---|---|---|
| 1 | 연결 상태 | **노드 이름** | 연결 상태 ❌ |
| 2 | 노드 이름 | **가속기 정보** | 가속기 정보 |
| 3 | 연결 해제 | **연결 상태** | 연결 해제 ❌ |

A-06-1 (2)도 같은 이유로 4번이 「심각도」에 붙어 있었다(절차문은 「조건」).

```bash
python3 $S/extract_docx.py <설명서.docx> /tmp/mk/doc   # uses.json 의 nums
```
→ 각 절차 문단이 실제로 참조하는 번호와 문장을 뽑아, **문장이 말하는 대상**에 박스를 둔다.

## 1. 표준 지오메트리

```
프레임      1500 × 654
이미지      (230, 60)  1040 × 524        # 비율이 다르면 §6-1 참조
좌 배지 열   x = 135        우 배지 열  x = 1319
좌 레일     x = 181        우 레일     x = 1319
배지        46 × 34, r6, fill #5283FF, stroke #000 2px INSIDE
배지 숫자    Inter Semi Bold 20, #FFF, 중앙 정렬(H·V), 박스와 동일 좌표·크기
리더선      2px #000 사각형, 긴 축 양 끝 ±1px 연장 (모서리 이 빠짐 방지)
점         6px 원 #000, 중심에서 −3 offset
영역선(실선) stroke #000 1px OUTSIDE, fill 없음      # 캡처에 실재하는 요소
영역선(점선) stroke #000 2px OUTSIDE, dash [6,4]     # "표시 자리"(모형)
halo       DROP_SHADOW #FFF a1, offset 0, radius 0, spread 1, showShadowBehindNode
```

**번호 순서**: 좌측 열 위→아래, 그다음 우측 열 위→아래.
`build.py`가 배지 위치를 보고 자동으로 매긴다. **손으로 번호를 정해 놓고
`--keep-numbers`를 쓰면 이 순서가 깨진다** — 설명서·명령문이 번호를 이미
참조할 때만 `--keep-numbers`를 쓰고, 그 밖에는 자동 재부여에 맡긴다.

**배지는 반드시 캡처 밖**(프레임 여백)에 둔다. 손으로 만드는 L5·L6에서 배지를
이미지 위에 올려 가리려던 UI를 덮은 적이 있다. 여백이 좁으면 프레임을 넓힌다.

## 2. 표준 워크플로우

```bash
S=~/.claude/skills/figma-screenshot-annotator/scripts
W=/tmp/mk && mkdir -p $W/img && cd $W
```

0. **번호의 뜻 확정** — §0-4. 절차문이 각 번호로 무엇을 가리키는지 먼저 확정한다.
1. **프레임 준비** — 원본 rect를 `clone()`해서 프레임에 넣는다. 원본은 절대 수정하지 않는다.
2. **렌더 내려받기** — `download_assets(nodeId=<클론된 rect>, scale=1)` → `img/<KEY>.png`
3. **영역 도출** — 서브에이전트(`references/subagent.md`) 또는 직접. 결과는 거친 seed 박스.
   요소의 **종류(MODE)**를 함께 적는다 — 이게 4단계의 입력이다.
4. **정합** — 종류가 분명하면 `fit.py`, 아니면 `snap.py`.

   ```bash
   python3 $S/fit.py  img/KEY.png --batch "nav,4,139,120,10;card,600,140,20,20"
   python3 $S/snap.py img/KEY.png "1,x,y,w,h;2,..."
   ```

   | MODE | 대상 | 안 쓰면 생기는 일 |
   |---|---|---|
   | `ink` | 글자·값·배지·아이콘 | — (seed 밖으로 절대 안 자람) |
   | `card` | 카드·표 전체 | 표 한 행으로 쪼그라듦 |
   | `nav` | 왼쪽 메뉴 항목 | **위아래 메뉴까지 삼킴** |
   | `row` / `band` | 목록의 한 행 | 표 전체를 삼킴 |
   | `panel` | 오른쪽 슬라이드오버 | 그림자만큼 왼쪽으로 밀림 |
   | `modal` | 딤 위의 창 | 딤된 뒤 카드를 잡음 |
   | `outline` | 흰 바탕 위 테두리 항목 | 안쪽 글자만 잡음 |
   | `solid` | 단색 채움 버튼·pill·아바타 | **버튼 색이 배경으로 뒤집혀** seed 그대로 나옴 |

   레일 폭 자동 탐지가 틀리면 `nav@150` 처럼 **직접 지정**한다.
   모드는 다크/라이트 테마 모두에서 검증돼 있다(다크 사이드바 · 밝은 회색 레일 ·
   축소된 아이콘 레일 · Nextcloud 흰 사이드바).

5. **겹침 해소** — `python3 $S/resolve.py "1,x,y,w,h;2,..."` → 부분 겹침만 물러난다.
6. **사전 검증** — `python3 $S/verify.py spec.json` → `empty / overlap / coarse / outside / tiny`
   **0건이 될 때까지 4~5를 반복**한다. 여기서 걸러야 할 것을 렌더에서 걸러온 게 반복 지적의 원인이었다.
   L3 표시 자리는 비어 있는 게 정상이므로 `"dash": [n]`으로 **의도를 적어** 예외 처리한다
   (적지 않으면 그냥 잘못 짚은 박스다).
7. **라우팅** — `areas.txt` 작성 후 `python3 $S/route.py`
   - 결과가 `cross=0 ovl=0 ink=0`이 아니면 영역을 줄이거나 나눈다
   - 이미지가 1040×524가 아니면 `IMGNAME@IMGX,IMGY,IW,IH`로 배치를 명시
8. **페이로드** — `python3 $S/build.py` → 재번호 + halo 판정 + 8개씩 분할
   - 설명서 번호를 유지해야 하면 `--keep-numbers`
9. **그리기** — 둘 중 하나. 좌표·스타일이 같아 결과도 같다.
   - Figma: `references/figma-plugin.md`의 스니펫으로 배치당 8프레임씩
   - 파일로: `python3 $S/render.py . --scale 2` → `out/<KEY>.png` (Figma 불필요)
10. **검증** — 개수 일치(badge=area=dot), 번호 연속/일치, 좌표 소수점 0, halo 전량 매칭
11. **육안 확인** — 렌더를 실제로 읽는다. 숫자만 맞고 위치가 틀린 경우가 반복해서 나왔다

## 3. 표현 수준 (L1~L6)

각 수준의 예시는 저장소의 `examples/`를 참조.

| 수준 | 언제 | 구성 |
|---|---|---|
| **L1** 기본 | 캡처에 요소가 다 보임 | 실선 영역 + 리더 + 배지 |
| **L2** 다크 대응 | 다크 사이드바·모달 딤 | L1 + 어두운 배경 요소에 halo |
| **L3** 표시 자리 | 스낵바·오류 문구 등 조건부 요소 | 모형(mock) 도형 + **점선** 영역 |
| **L4** 확대 도해 | 표 안 작은 컨트롤 | CROP 확대 패널 + 점선 연결선 |
| **L5** 상태 카탈로그 | 한 지점의 상태가 여러 개 | 캡처 1개 + pill 모형 그리드 |
| **L6** 조건 대조 | 빈 상태 ↔ 데이터 있는 상태 | 2-up + 변화 영역만 지목 |

세부 스타일은 `references/style.md`.

## 4. 설명서 연동 (매뉴얼 .docx)

```bash
python3 $S/extract_docx.py <manual.docx> /tmp/mk/doc
# -> labels.json  shotKey -> [[번호, UI요소, 설명], ...]   (2.2 화면 구성 표)
# -> uses.json    [{shot, head, table, nums}]             (2.2 + 2.3 절차)
# -> gaps.json    "※ ...스크린샷이 준비되지 않아" 표기
# -> media.json   shotKey -> word/media 파일명
```

- 설명서의 **번호·라벨 표가 정답**이다. 번호를 늘리거나 줄이지 않는다.
- 같은 화면이 `2.2 화면 구성`(전체)과 `2.3 조작 절차`(일부)에서 쓰인다.
  절차판은 참조된 번호만 남긴 **variation**으로 따로 만든다.

**파일명에 의존하지 말 것.** Word가 저장할 때마다 미디어를 전부
`image_shot05.png` → `image108.png` 식으로 renaming한다. 그래서 분류는 픽셀 크기로 한다
(번호 배지 = 작고 여러 번 재사용 / 스크린샷 = 폭 ≥ 800). 배지의 **번호는 화면 구성 표의
행 순서**에서 얻고, 표는 헤더에 `번호`·`UI 요소`가 있는 것만 인정한다.

**"화면 구성 표가 없는 스크린샷 N건" 경고가 뜨면** 절차판이 2.2와 다른 캡처를 쓰고 있다는
뜻이다. 어느 표를 따를지는 **수동으로 연결**한다. 비슷한 이미지끼리 자동으로 묶으려다
서로 다른 관리자 화면(다크 사이드바·레이아웃 공통)이 합쳐져 라벨이 뒤섞인 적이 있어,
지금은 **바이트 동일**할 때만 묶는다.

### 4-1. 반대 방향 — Figma 렌더를 문서에 밀어 넣기

```bash
# 프레임을 2배로 내려받으면 문서의 기존 규격(3000×1308)과 정확히 같다
download_assets(nodeId=<프레임>, defaultScale=2)

python3 $S/sync_docx.py <설명서.docx> out.docx <png디렉터리> map.json
```

`map.json`은 **캡션(`[화면 이름]`) 순서**로 이미지를 짝짓고, 텍스트 수정은
`section`(절 제목) 범위 안에서만 한다. 파일명·문단 인덱스에 의존하지 않는다.

넘어야 할 함정 넷 — 전부 실제로 당했다:

| 함정 | 증상 | 대응 |
|---|---|---|
| 한 미디어를 여러 절차가 공유 | 세 절차가 같은 그림이 됨 | 두 번째부터 새 파트로 분리 |
| 비율이 바뀜 | 세로로 눌려 보임 | `extent`의 `cy` 재계산 |
| `1. 입력` 같은 단계 제목이 수십 번 | **딴 절이 수정되고 문단이 날아감** | 절 범위 안에서만 검색 |
| 하이퍼링크 안의 글자 | `일반 탭화면설명 11.1` 찌꺼기 | 문단 통째 교체(`hard`) |

마지막에 **원본과 텍스트 diff**를 떠서 의도한 줄만 바뀌었는지 확인한다.
`[Content_Types].xml`은 zip의 첫 항목이어야 한다.

### 4-2. 기능이 바뀌면 이미지만 바꿔서는 안 된다

캡처를 새 것으로 갈았는데 설명이 옛 기능을 말하고 있으면 그 절은 **다시 써야** 한다.
(「기본 워크스페이스 이름」 입력 칸이 「관리자 메뉴 기본 상태」 펼침/접힘 선택으로
바뀌어, A-09-1 절차 전체와 11.1 화면 구성 표를 함께 고쳤다.)

같이 손대야 하는 것: **절차 문장 · 단계 제목 · 화면 구성 표의 UI 요소/설명 ·
참조 표 · 그리고 2.2와 2.3 양쪽 이미지.**

## 5. 흔한 실패 (실제로 겪은 것만)

| 증상 | 원인 | 대응 |
|---|---|---|
| 박스가 2~16px 어긋남 | 프리뷰 눈대중 | `snap.py` 필수 |
| 위치별로 다르게 밀림 | FILL crop ≠ 로컬 사본 | §0-1 |
| 확대 표시 위치 불일치 | 밴드별 y 오프셋 혼용 | §0-2, 크롭 변수 1개에서 파생 |
| 프레임이 섹션 밖으로 | 절대좌표 대입 | §0-3 |
| 플러그인 전체 롤백 | `createLine().resizeWithoutConstraints(w)` | **height 인자 필수** |
| 섹션이 안 보임 | `createSection()`이 현재 페이지에 생성 | `setCurrentPageAsync` 먼저 |
| halo 누락 | "평균 휘도 < 125" 기준 | **<140 픽셀 비율 ≥ 20%** |
| 이름 조회 실패 | 한글 rect 이름 사전 조회 | 노드 id로 접근 |
| 메뉴 박스가 3줄을 삼킴 | `snap`의 블롭이 이웃 행으로 번짐 | `fit.py nav` |
| 표 박스가 한 행으로 쪼그라듦 | 행 구분선 색이 페이지 배경과 근사 | `fit.py card` (연속 3px 규칙) |
| 패널 박스가 16px 왼쪽 | 그림자를 요소로 인식 | `fit.py panel` (열 평균 휘도) |
| 모달 대신 뒤 카드를 잡음 | 딤된 카드도 "배경이 아님" | `fit.py modal` (순백 성분) |
| 박스끼리 살짝 물림 | 이웃 요소를 seed에 포함 | `resolve.py` (포함은 허용, 부분 겹침만) |
| 번호는 맞는데 대상이 틀림 | 화면 구성 표 라벨로 그림 | **§0-4** 절차문 기준 |
| 설명과 화면이 안 맞음 | 캡처가 구버전 | **§6-5** 최신 캡처로 교체 |
| 박스가 이미지 밖 | 1040 아닌 캡처에 기본 원점 사용 | `IMGNAME@IMGX,IMGY,IW,IH` |
| 섹션 복제 후 프레임이 전부 밖으로 | 섹션 이동 시 자식에도 델타를 더함 | **§0-3** — `sec.y` 한 줄 |
| 문서에서 세 절차가 같은 그림 | 미디어 파트 공유 | §4-1 새 파트로 분리 |
| 문서 문단이 딴 절로 날아감 | 절 범위 없이 `1. 입력` 검색 | §4-1 `section()` 범위 |
| nav가 레일 전체를 삼킴 | 옅은 강조(#E6F4F1 on #F1F4F3) | `fit_nav` 오차를 넓혀 가며 한도 내 마지막 값 |
| nav가 몇 줄로 쪼그라듦 | 그라데이션 강조에 좁은 오차 | 위와 같은 스윕이 해결 |
| 레일 폭을 못 찾음 | "어두운 열" 기준 = 다크 전용 | `rail_width()` — 세로 경계선으로 탐지 |
| card가 즉시 무너짐 | 흰 카드가 많아 카드색=페이지 배경 | `_page_bg()` — 아래·오른쪽 여백 띠에서 뽑기 |
| 모달이 띠 하나로 잘림 | 창 안 가로 구분선에서 멈춤 | `fit_modal` — 3줄까지 건너뜀 |

## 6. 예외 처리

### 6-1. 원본 비율이 1040:524와 다를 때

둘 중 하나를 고른다. **섞지 않는다.**

- **(A) 규격 유지** — 1040×524에 그대로 넣고 crop을 수용. 반드시 §0-1대로 export를 측정한다.
- **(B) 비율 유지** — 이미지 높이를 `1040 × H/W`로, 프레임 높이를 `+130`으로 조정.
  Word 문서의 이미지 규격이 흐트러지므로 사용자에게 확인한다.

### 6-2. 대비가 낮아 `snap.py`가 `no-ink`일 때

연회색 테두리 카드(#E5E7EB on #F8F9FB)가 여기 해당한다. 흰색 런으로 직접 잰다.

```python
col = a[:, X]                      # 카드를 가로지르는 열
white = np.all(col >= 250, axis=1) # 카드 내부는 순백
# 연속 구간의 시작/끝이 카드의 상/하단
```

### 6-3. 박스가 겹칠 때

**포함(containment)은 허용, 부분 겹침은 결함이다.**

- 포함 — 「카드」와 그 안의 「값」, 「표」와 그 안의 「열」. 독자는 영역과 그 안의 항목으로 읽는다.
- 부분 겹침 — 두 박스가 모서리만 물린 상태. 그냥 그리다 만 것처럼 보인다.

```bash
python3 $S/resolve.py "3,394,265,252,38;4,595,267,53,34"
# -> 큰 쪽이 2px 여백을 두고 물러난다 (작은 쪽은 건드리지 않는다)
```

포함으로 만들 수 없는데 겹치면 **seed가 이웃 요소를 물고 있다는 뜻**이다. 먼저 seed를 좁힌다.

### 6-4. 캡처에 없는 조건부 요소 (스낵바·오류 문구)

지우거나 다른 캡처를 끌어오지 말고 **L3 표시 자리**로 그린다 —
모형 도형 + **점선 2px OUTSIDE dash [6,4]**. 실선과 섞으면 "캡처에 있는 것"으로 읽힌다.
(A-06-2 #5 「실행 결과 알림」이 9/15 캡처에서 사라져 이 방식으로 처리했다.)

### 6-5. 설명과 화면이 어긋나면 **구버전 캡처를 의심**한다

박스 위치를 아무리 고쳐도 설명이 가리키는 요소가 화면에 **없으면** 좌표 문제가 아니다.

점검 순서:

1. 절차문이 언급하는 단어가 캡처 안에 실제로 있는지 본다
   (예: 「해결 전 확인」 → 현재 UI는 「지시사항」, 「볼륨 보기」 버튼이 새로 있음).
2. 같은 화면의 최신 캡처가 파일 안에 이미 올라와 있는지 찾는다(스크린샷 업데이트 섹션).
3. 프레임을 새로 만들지 말고 **fill의 `imageHash`만 교체**한다.

```js
const src = await figma.getNodeByIdAsync('<최신 캡처 rect>');
rect.fills = [{type:'IMAGE', scaleMode:'FILL', imageHash: src.fills[0].imageHash}];
```

4. 교체하면 좌표계가 달라진다 — **§0-1대로 export를 다시 받아** 전 박스를 다시 정합한다.
5. 캡처가 바뀌어 설명서 문장이 틀려진 부분은 **문서 수정 목록으로 보고**한다(이미지에서 임의 보정 금지).

## 7. 검증 체크리스트

작업 종료 선언 전에 **전부** 통과해야 한다.

- [ ] `verify.py` 0건 — **empty(빈 공간) / overlap(부분 겹침) / coarse / outside / tiny**
- [ ] 각 번호가 **절차문이 말하는 대상**에 붙어 있음 (§0-4)
- [ ] 절차문의 단어가 캡처에 실재함 — 없으면 구버전 캡처 (§6-5)
- [ ] 캡처에 없는 조건부 요소는 **점선**, 실재 요소는 **실선** (§6-4)
- [ ] 라우팅 `cross=0 ovl=0 ink=0`
- [ ] 프레임별 `badge == area == dot`
- [ ] 번호 1..N 연속 (또는 설명서 번호와 정확히 일치)
- [ ] 좌표 소수점 0개
- [ ] halo 지정분 전량 매칭 (`unmatched: []`)
- [ ] 프레임이 섹션 경계 안 (`inside=true`)
- [ ] 섹션이 페이지의 다른 노드와 겹치지 않음
- [ ] **렌더를 눈으로 확인** — 숫자만 맞고 위치가 틀린 사례가 반복됨

문서에도 반영했다면:

- [ ] 원본과 **텍스트 diff** — 의도한 줄만 바뀌었는지 (§4-1)
- [ ] 절차 이미지가 **전부 고유 파트**인지 (공유 파트 잔존 = 같은 그림 반복)
- [ ] 바뀐 이미지의 **비율/크기**가 기존 규격과 같은지
- [ ] 기능이 바뀐 절은 **2.2 화면 구성 표·참조 표까지** 함께 고쳤는지 (§4-2)

> 기존 작업을 고칠 때는 **섹션을 `clone()`해 새 버전에서** 고친다. 이전 버전은 대조용으로 남긴다.
> 문서는 반드시 **타임스탬프 백업**을 먼저 뜬다.
