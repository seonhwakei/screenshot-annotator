# 콜아웃 영역 도출 서브에이전트

화면을 보고 "무엇을 짚을지"는 판단이 필요하다. 이 부분만 서브에이전트에 맡기고,
좌표 보정(`snap.py`)·배선(`route.py`)·그리기는 결정론적으로 처리한다.

- 화면 4~5장씩 묶어 병렬로 돌린다. 한 에이전트에 10장 이상 주면 품질이 떨어진다.
- 결과는 **거친 seed 박스**로 취급한다. 반드시 `fit.py`/`snap.py`를 통과시킨다.
- 절차판이면 라벨을 **절차문에서** 뽑아 준다(SKILL.md §0-4). 화면 구성 표의 라벨을
  그대로 쓰면 번호는 맞고 대상이 틀린다 — 실제로 A-04-2, A-06-1에서 그렇게 틀렸다.
- 좌표와 함께 **MODE**(ink/card/nav/row/band/panel/modal/outline)를 받는다.

## 규칙
- 화면당 5~9개. 설명 가치가 있는 것만.
- 좌표는 그 **이미지 자체의 1040x524 픽셀 좌표**(좌상단 0,0), 정수.
- 박스는 요소를 꽉 맞게 감쌀 것(여백 2~4px). 거대한 박스 금지.
- 같은 화면 안에서 박스끼리 겹치면 안 됩니다.
- "메뉴"류는 좌측 네비의 해당 항목 행만, "목록 헤더"는 표의 헤더 행만,
  "행"은 데이터 행만 감싸세요.
- 라벨은 한국어로 짧게 (예: "새로고침 버튼", "노드 상태 배지").
- 번호는 1..N, 순서는 자연스러운 대로. 이후 재부여됩니다.

## 모호할 때 붙이는 힌트

한 번씩 실제로 틀렸던 곳들. 해당하면 프롬프트에 직접 적어준다.

- 모달이 떠 있는 화면에서 **`(헤더)`가 붙은 라벨은 창 뒤 본문의 버튼**,
  괄호 없는 동명 라벨은 창 안의 요소.
- `(버튼)`이 붙은 라벨도 창 뒤 본문 버튼을 가리킨다.
- **묶음 라벨과 개별 라벨이 같이 있으면**(예: "요약 카드" + "활성 규칙")
  개별 쪽을 우선 배치하고 묶음 쪽은 나머지만 감싼다.
- **"관리자 메뉴"(전체)와 "감사 로그 메뉴"(항목)가 함께 있으면**
  전체 쪽에서 항목 행을 제외한다.
- 탭이 여럿 보이는 설정 화면은 1·2·3이 각 **탭 버튼**,
  4는 현재 탭의 **설정 항목 라벨**, 5는 **입력 칸**, 6은 **저장 버튼**.

## 받은 뒤 반드시 하는 것

```bash
python3 $S/fit.py     img/KEY.png --batch "MODE,x,y,w,h;..."   # 종류를 아는 경우
python3 $S/snap.py    img/KEY.png "1,x,y,w,h;..."              # 종류가 애매한 경우
python3 $S/resolve.py "1,x,y,w,h;2,..."                        # 부분 겹침 해소
python3 $S/verify.py  spec.json                                # 0건이 될 때까지
```

- `moved0~4` — 정상
- `moved10+` — 요소를 잘못 짚었을 가능성. 라벨 대조를 다시 한다
- `no-ink` / `no-ink->card` — 저대비 카드. 결과를 육안 확인한다

`verify.py`가 0건이 된 뒤에야 라우팅으로 넘어간다.
