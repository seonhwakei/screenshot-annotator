# agent-browser 서비스 동선 캡처 스킬 모음

`agent-browser`로 서비스 화면을 여러 레인이 동시에 촬영하고, 컷을 모아 Figma에 올려 정리하는 데 쓰는 Claude Code 스킬 7개입니다.
설치: `skills/<이름>` 폴더를 `~/.claude/skills/` 아래로 복사하면 됩니다. 화면에 마크업(번호·박스)을 그리는 스킬은 이 레포의 [`skills/screenshot-annotator`](../skills/screenshot-annotator)를 쓰세요.

> 비유: 사진사 여러 명이 앱 화면을 한 컷씩 찍어 앨범(Figma)에 정리하는 과정입니다. 아래 스킬은 사진사 관리, 촬영 규칙, 앨범 정리 도구입니다.

## 한눈에 보기

| 단계 | 스킬 | 한 줄 설명 |
|---|---|---|
| 촬영 준비 | `agent-browser-session-login` | 로그인을 한 번만 하고 저장해서 재사용하는 법 |
| 촬영 중 | `agent-browser-parallel-lanes` | 사진사(세션)가 멈췄을 때 그 사람만 다시 부르는 법 |
| 촬영 중 | `feature-guide-screenshot-lanes` | 기능별로 사진사를 나눠 찍는 규칙(한국어 화면, 컷 설명) |
| 촬영 중 | `feature-guide-defect-recapture` | 찍다가 앱 버그를 발견했을 때의 처리 순서 |
| 정리 | `feature-guide-cut-assembly` | 여러 사진사의 결과를 한 번에 합치는 법 |
| 정리 | `figma-image-upload` | PNG를 Figma 페이지에 올리고 크기·위치·라벨 맞추기 |
| 검증 | `live-page-verification` | 실제 운영 페이지의 이미지·콘솔 오류를 확인하는 법 |

## 스킬별 설명 (전달용)

### agent-browser-session-login — 로그인 한 번, 계속 재사용
- **무엇**: 레인(계정)마다 세션 이름을 따로 주고, 로그인이 진짜 성공했는지 주소로 확인한 뒤 상태 파일로 저장·재사용합니다.
- **언제**: agent-browser가 로그인이 필요하거나 저장된 로그인 상태를 쓰고 싶을 때.
- **쉽게**: 출입증을 한 번 발급받아 지갑에 넣어두고, 다음부터는 그 출입증으로 바로 들어가는 방법입니다. 출입증 파일은 레포 밖에 두고 비밀번호는 채팅에 붙이지 않습니다.

### agent-browser-parallel-lanes — 멈춘 레인만 복구
- **무엇**: 레인마다 별도 세션을 쓰고, `daemon busy`·`connection refused`가 나면 해당 세션만 닫고 다시 엽니다. 전체 종료(`close --all`)는 금지합니다.
- **언제**: 여러 레인을 동시에 돌리다 세션이 멈추거나 연결이 거부될 때.
- **쉽게**: 한 명이 쓰러졌다고 전원을 퇴근시키지 말고, 그 사람만 교체하라는 규칙입니다.

### feature-guide-screenshot-lanes — 기능별 레인 촬영 규칙
- **무엇**: 기능 영역 하나를 레인 하나로 맡깁니다. 화면은 `/ko`(한국어)로 찍고, 컷마다 `captions.json`(제목·설명·단계·상태 OK/MOCKED/BLOCKED)을 씁니다. 프로세스 종료는 반드시 대상을 확인한 뒤에만 하고, 삭제·발행처럼 되돌릴 수 없는 버튼은 이름이 아니라 고유 id로 누릅니다.
- **언제**: 기능별 사용자 가이드 스크린샷을 찍거나 다시 찍을 때.
- **쉽게**: "한국어 화면으로, 사진마다 설명을 붙여서, 위험한 버튼은 신중히" 찍으라는 촬영 수칙입니다.
- **주의**: 원본은 로컬 개발 환경 기준입니다. 주소(`<app-url>`)와 포트는 대상 환경에 맞게 바꿔 쓰세요. 이 스킬이 가리키는 `feature-guide-local-seeding`, `asr-writer`는 이 모음에 포함되어 있지 않습니다.

### feature-guide-defect-recapture — 버그 발견 시 처리 순서
- **무엇**: 촬영 중 앱 결함을 발견하면 결함 기록, 수정, 해당 동선 재촬영 순서로 처리합니다. 앱이 이상하다는 이유로 그 컷을 포기하지 않습니다.
- **쉽게**: 사진을 찍다 가게 간판이 부러진 걸 봤다면, 포기하지 말고 고친 뒤 다시 찍으라는 뜻입니다.

### feature-guide-cut-assembly — 컷 합치기
- **무엇**: 레인 결과를 재실행 가능한 스크립트 하나로 합칩니다. 레인 접두어(`G_` 등)를 붙이고, BLOCKED 컷은 건수를 출력하며 제외합니다. 캡션과 PNG가 서로 짝이 맞는지 확인하고, 컨택트 시트로 눈으로 점검한 뒤 올립니다.
- **쉽게**: 여러 사람이 찍은 사진을 앨범에 넣기 전에 번호표를 붙이고 빠진 것·불량을 골라내는 작업입니다.

### figma-image-upload — Figma에 올리고 정리
- **무엇**: 로컬 PNG를 Figma 특정 페이지에 올리고, 원본 픽셀 비율로 크기를 보정해 잘림을 막고, 그리드 배치와 라벨까지 정리합니다. `figma-remote` MCP 기준입니다. 올린 뒤에는 스크린샷으로 잘림 여부를 직접 확인합니다.
- **쉽게**: 사진을 앨범에 붙일 때 모양이 안 잘리게 크기를 맞추고, 칸을 맞춰 설명 글까지 달아주는 방법입니다.

### live-page-verification — 실제 페이지 확인
- **무엇**: 페이지를 끝까지 스크롤해 늦게 로드되는 이미지까지 확인하고, 콘솔 404는 실제 링크 주소로 다시 점검합니다. 확인한 것과 확인하지 못한 것을 구분해 보고합니다.
- **쉽게**: 완성된 가게를 직접 한 바퀴 돌며 문제없는지 보고, "봤다/못 봤다"를 솔직하게 적는 점검표입니다.

## 포함하지 않은 것
- Nadoo Cloud 전용 스킬(`nadoo-capture`, `dgx-e2e`): 사내 장비·주소·문서 구조가 많이 들어 있어 제외했습니다.
- 자동 생성 파일(`.ledger.jsonl`, `.sidecar.json`, `evidence-*.md`): 작업 로그라 제외했습니다.
